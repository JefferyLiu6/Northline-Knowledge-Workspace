# AI RAG Knowledge Base Platform Database Setup

For the verified Docker installation, use the [reproducible local setup guide](docs/LOCAL_SETUP.md). This document covers the alternative manual database, Python, and npm setup.

The platform uses MySQL for users, knowledge bases, documents, chunks, model settings, retrieval strategies, chats, agent runs, and evaluations. PostgreSQL with pgvector stores embeddings and the metadata used to filter vector searches. The two databases link through `knowledge_chunk_vector.chunk_id` in PostgreSQL and `knowledge_chunk.id` in MySQL.

## 1. Import the sample databases

Install MySQL 8 or later, PostgreSQL with the pgvector extension, Python 3.12, and Node.js. Use fresh databases for the demo. The import scripts drop and recreate their tables, so rerunning them replaces existing data in those tables.

Create the MySQL database with the `utf8mb4` character set and `utf8mb4_unicode_ci` collation. From the project root, run:

```sh
mysql -u root -p -e 'CREATE DATABASE ai_rag CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci'
mysql -u root -p ai_rag < ai_rag.sql
```

Create the PostgreSQL database and import the pgvector dump:

```sh
createdb -U postgres ai_rag_vector
psql -X -v ON_ERROR_STOP=1 -U postgres -d ai_rag_vector -f ai_rag_vector.sql
```

The PostgreSQL server must have pgvector installed, and the import account needs permission to create the extension. In Navicat, select the matching database and choose **Run SQL File** for each dump.

The MySQL dump contains 25 tables, three sample knowledge bases, 11 sample documents, 121 chunks, three Q&A apps, and examples of chats, agent runs, and evaluations. The PostgreSQL dump contains 110 vectors. The other 11 chunks are parent chunks, which provide context after retrieving their child chunks.

## 2. Start the backend and frontend

Update the MySQL and PostgreSQL connection settings in `ai_rag/fastapi-app/settings.py` to match your installation. The defaults use local ports 3306 and 5432. Keep the PostgreSQL embedding dimension at 1024 while using the supplied schema.

From `ai_rag/fastapi-app`:

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

On Windows, activate the environment with `.venv\Scripts\activate`. The backend listens on port 9090.

In a second terminal, from `ai_rag/vue`:

```sh
npm ci
npm run build
npm run preview -- --host 127.0.0.1 --port 5173 --strictPort
```

Open the frontend at `http://127.0.0.1:5173`. Use `npm run dev` when editing the frontend. The seeded accounts are:

## 3. Run the AI models with local Ollama

Start Ollama and make these models available locally:

```sh
ollama pull llama3.1:8b
ollama pull mxbai-embed-large:latest
```

The supplied MySQL dump enables the following configurations in **AI Model Configuration**. They use the base URL `http://127.0.0.1:11434/v1` and the API-key placeholder `ollama`. The Full retrieval strategy uses Ollama to score candidate passages on relevance. [Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility#local-server-usage)

| Configuration | Model |
| --- | --- |
| Ollama chat | `llama3.1:8b` |
| Ollama embeddings | `mxbai-embed-large:latest` |
| Ollama reranker | `llama3.1:8b` |

The PostgreSQL dump includes 110 embeddings generated by `mxbai-embed-large:latest`. Importing both scripts with that model gives you a ready-to-query vector index. The seed includes all 11 prompt templates.

### Rebuild embeddings after switching models

If you change the embedding model, clear the affected knowledge bases' embeddings to reset their model bindings, then use **Embed** in **Document Management** for each document. Verify the result in each knowledge base's embedding status. Keep the model output dimension, `PGVECTOR["dimension"]`, and the table's `vector(1024)` column in agreement.

## 4. Resolve common setup errors

| Symptom | Check |
| --- | --- |
| MySQL reports no database selected | Create `ai_rag` and select it before running the script. |
| Text appears garbled | Import the scripts as UTF-8 and use `utf8mb4` for MySQL. |
| PostgreSQL reports that the vector type is missing | Install pgvector for the PostgreSQL server and verify that the import account can create the extension. |
| PostgreSQL reports an object conflict during import | Confirm you are connected to the intended `ai_rag_vector` database. |
| The backend cannot reach PostgreSQL | Confirm the service is running and compare the host, port, username, and password with `PGVECTOR` in `settings.py`. |
| An AI request fails | Verify that the relevant model is enabled and that its API key, base URL, and protocol are configured. |
| A question returns no matches | Check the document embedding status and the selected retrieval strategy's score threshold. |

The application and database seeds use matching status and option values. Migrate records before switching an existing installation to a different schema or status vocabulary.

## Security migration and test databases

Existing plaintext passwords are converted to salted hashes at startup; login passwords remain unchanged. Fresh imports already contain hashes. Set a private JWT_SECRET of at least 32 characters, or let the app generate its ignored .local-jwt-secret file. Existing sessions signed with the previous repository key are invalid and require a new login.

Connection environment overrides are MYSQL_HOST, MYSQL_PORT, MYSQL_DATABASE, MYSQL_USER, MYSQL_PASSWORD and PGHOST, PGPORT, PGDATABASE, PGUSER, PGPASSWORD. Regression tests require both database names to end in _test or _check. Import the same seeds into these separate databases; never point the suite at the normal app databases.

The development browser origins permitted by CORS are http://127.0.0.1:5173 and http://localhost:5173. Use a consistent hostname for the frontend and backend so the file-download session cookie is sent. File downloads require login; expired sessions must sign in again.
